# IDE Integration

<PlanCompatibility features={["ai"]} />

Nutze mittwalds [DSGVO-konforme KI-Modelle](/docs/v2/platform/aihosting) direkt in deiner Entwicklungsumgebung für Code-Generierung, Vervollständigung, Refactoring und Debugging. Alle Modelle werden in Deutschland gehostet, ohne Nutzerdaten zu speichern oder zum Training zu verwenden.

## Verfügbare Modelle

Der Service bietet mehrere Modelle für unterschiedliche Entwicklungsaufgaben. Eine vollständige Liste findest du in der [Dokumentation zu KI-Modellen](/docs/v2/platform/aihosting/models).

**Empfohlene Modelle:**

- **DeepSeek-V4.1-Flash-1017**: das größte Modell in unserem Angebot und unsere Empfehlung für Coding-Agenten – 1.048.576 Token
  Kontext, Bild-Input, Tool Calling. Es ist in der
  [Testphase](/docs/v2/platform/aihosting/access-and-usage/lifecycle#testphase)
- **Qwen3.8-27B-NVFP4**: die Stable-Wahl für den Produktivbetrieb, 256.000 Token Kontext,
  bis zu 16 Bilder pro Anfrage
- **Qwen3.6-35B-A3B-FP8**: das schnellste der Coding-Modelle, 256.000 Token Kontext, gut für
  Completion und schnelle Edits
- **Kolibri-1**: Chat und Texte auf Deutsch, 1.048.576 Token Kontext, nur Text.
  Es ist in der [Testphase](/docs/v2/platform/aihosting/access-and-usage/lifecycle#testphase)
- **gpt-oss-120b**: nur Text, Lifecycle LTS, 131.072 Token Kontext
- **Ministral-3-14B-Instruct-2512**: klein und schnell, 262.144 Token Kontext, für
  leichtgewichtige Assistenten

## Schnellstart

1. **AI-Hosting-API-Key holen**: Siehe [API-Key einrichten](/docs/v2/platform/aihosting/access-and-usage/access)
2. **IDE wählen**: Eine der Integrationen oben nutzen
3. **Endpoint konfigurieren**: `https://llm.aihosting.mittwald.de/v1`
4. **Modell wählen**: `DeepSeek-V4.1-Flash-1017`, oder `Qwen3.8-27B-NVFP4`, wenn du ein Stable-Modell brauchst

## Best Practices

### Modellwahl

- **DeepSeek-V4.1-Flash-1017**: Startpunkt für agentic Coding, Refactoring und Tool Use.
  Setz das Kontextfenster auf 1.048.576 Token und `max_tokens` auf mindestens 32.768, denn
  das Modell denkt nach, bevor es antwortet. Für schwieriges Reasoning und kniffliges
  Debugging setz `reasoning_effort: "max"`
- **Qwen3.8-27B-NVFP4**: Produktiv-Setups, die ein Modell mit dem Status Stable brauchen
- **Qwen3.6-35B-A3B-FP8**: Inline-Completion und schnelle Edits, wo Latenz mehr
  zählt als Tiefe
- **Kolibri-1**: Chat und Texte auf Deutsch. Es ruft Tools nur mit
  `tool_choice: "auto"` auf, nutze es also nicht mit Agenten, die einen Tool-Aufruf erzwingen
- **gpt-oss-120b**: Automatisierungen, die den Lifecycle LTS brauchen und nur Text verarbeiten
- **Ministral-3-14B-Instruct-2512**: leichtgewichtige Assistenten und einfacher Chat

### Tipps für Long Context {#long-context-tips}

- Nicht das ganze Repo senden, nur relevante Dateien/Funktionskörper
- Vorherige Schritte zusammenfassen und IDs/Anker für Rehydration nutzen
- Antworten streamen, `max_tokens` nur bei Bedarf erhöhen
- Für Tools/Edits deterministisch bleiben: `temperature <= 0.2`. Reasoning-Modelle wie
  DeepSeek-V4.1-Flash-1017 und Kolibri-1 sind die Ausnahme: Behalte die Sampling-Parameter
  von ihren Modellseiten bei
- Repo-Scope bewusst klein halten, gezielt einzelne Dateien/Funktionen anfragen
- Bei Orchestrierung mehrstufiger Änderungen bevorzugt strukturierte Outputs (JSON/Tool-Output) nutzen

### MCP Server Integration

Viele IDEs unterstützen [Model Context Protocol (MCP)](/docs/v2/agentic-integration/mcp/) Server für erweiterte Fähigkeiten:

- **Context7**: Aktuelle Library-Dokumentation
- **Brave Search**: Websuche mit Privacy-Fokus
- **Directus**: Headless-CMS-Management
- **OpenSearch**: Suche, Index-Inspektion, Mappings und Cluster-Diagnostik
- **TYPO3**: TYPO3-CMS-Content und Backend-Automatisierung per MCP
- **mittwald**: Infrastruktur-Management in natürlicher Sprache

Für eine breitere Ökosystem-Liste siehe die [MCP-Server-Registry](https://github.com/modelcontextprotocol/servers).

Details zur MCP-Konfiguration findest du in den jeweiligen IDE-Guides.
