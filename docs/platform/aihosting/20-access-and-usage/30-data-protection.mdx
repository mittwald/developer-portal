## Place of processing {#place-of-processing}

All processing takes place on infrastructure that mittwald operates in Germany. Data is transmitted exclusively in encrypted form (HTTPS). Request content isn't disclosed to third parties. If you access AI hosting from a mittwald hosting product, processing takes place entirely within mittwald's infrastructure.

## Request content {#content}

Request content comprises all data you submit to a model and all output the model returns, in particular prompts, messages, images, audio, documents, reasoning output, tool calls, and embeddings.

Request content is processed exclusively in volatile memory, solely for the purpose of generating the response, and is deleted once the request has been completed. Request content isn't written to logs, databases, or other persistent storage. This also applies to requests that fail or are rejected, for example because a rate limit has been exceeded.

Request content isn't used to train, fine-tune, or otherwise improve models. The models aren't self-learning; each model remains in the state in which it was published.

**Exception: response cache.** To answer identical requests efficiently, a completed response can be held in a cache in volatile memory for a maximum of 60 seconds. If a byte-identical request is received within this period, it's answered from the cache. The request itself is held in the cache only as a cryptographic hash value. The cache isn't written to persistent storage and is deleted automatically after 60 seconds.

## Metadata {#metadata}

For the purposes of operating the service, ensuring its security, investigating errors, and billing, mittwald processes metadata about each request. Metadata doesn't include any request content.

| Category                        | Data                                                                                                                                                                                                                                    | Purpose                        | Retention period                                      |
| ------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------ | ----------------------------------------------------- |
| Access logs                     | Timestamp, IP address, requested path, status code, data volume, user agent                                                                                                                                                             | Operation, security            | 7 days                                                |
| Application and error logs      | Timestamp, error type, status code, model, request ID, IP address truncated to the network prefix (IPv4 /24, IPv6 /48)                                                                                                                  | Operation, error investigation | 7 days; error reports approximately 30 days           |
| Operating metrics               | Aggregated counters per model and pseudonymized API key, such as number of requests, response times, error rate, and number of tokens                                                                                                   | Operation, capacity planning   | 14 days                                               |
| Usage data                      | Per request: timestamp, model, endpoint, number of input and output tokens, costs, status, user agent, hash value of the API key, name of the API key, project, and the optional `user` parameter; daily totals per project and API key | Billing                        | [TBD: statutory retention period for billing records] |
| Client IP address in usage data | IP address of the client that sent the request                                                                                                                                                                                          | Security, abuse prevention     | 30 days                                               |

Backup copies of usage data are retained for 4 weeks and are then overwritten. All other metadata is deleted automatically and on a continuous basis once its retention period has expired. The sole deletion criterion is the age of the data.

:::tip[Avoid personal data in metadata fields]
The optional `user` parameter and the names of your API keys and projects are stored as metadata. Use only pseudonymous identifiers in these fields, and don't enter names, email addresses, health data, or other special categories of personal data.
:::

## Shared and dedicated AI hosting {#shared-dedicated}

In shared AI hosting, requests from different customers are processed on the same hardware and the same model instances. Each request is processed separately and doesn't modify the model. [TBD: paragraph on separation between customers.]

In [Dedicated AI hosting](../70-dedicated/index.mdx), the GPUs and the complete stack, from the gateway through the model servers to the endpoint, are reserved exclusively for you. Requests from other mittwald customers aren't processed on this infrastructure. If you make dedicated capacity available to your own customers, the description of shared AI hosting applies to them accordingly, with you as the operator. If you have administrative access to your dedicated gateway, you're responsible for any additional logging you enable there.

## Processing in your own applications {#applications}

If your application stores model output or embeddings, that storage takes place in the services and hosting products your application uses and is outside the scope of AI hosting. For example, if you run Open WebUI in mittwald's container hosting, chat histories and uploaded documents are stored in that container's storage.

Whether a specific application complies with the GDPR, the EU AI Act, or other legal requirements depends on its purpose and design. Where personal data is processed, consent from the data subjects may be required. The Terms of Use apply.
