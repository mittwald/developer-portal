:::note
You are responsible for using AI hosting in a way that complies with data protection law in your use case. That includes consent, purpose limitation, and how you design the AI functionality.
:::

All models run on infrastructure that mittwald operates in Germany. Requests are encrypted in transit (HTTPS) and aren't passed to third parties. If you call AI hosting from a mittwald hosting product, your data never leaves mittwald's infrastructure.

## What we don't store {#content}

We don't store the content of your requests or the model's answers: prompts, messages, images, audio, documents, reasoning output, tool calls, or embeddings. The content is processed in memory while the request runs and is discarded afterwards. This also applies to requests that fail or are rejected, for example because of a rate limit.

The models don't learn from your requests. Each model stays in the state in which it was published, and your data isn't used to train or improve any model.

There's one short-lived exception: a completed answer can be held in an in-memory cache for up to 60 seconds. If a byte-identical request arrives within that time, it's answered from the cache. The cache is never written to disk, and the request itself is only kept as a hash that identifies it in the cache.

## What we store {#metadata}

To operate the service, bill usage, and investigate errors, we store metadata about each request. Metadata never includes the content of a request or an answer.

| Data                       | Contents                                                                                                                                                                                                                 | Retention                                      |
| -------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ---------------------------------------------- |
| Access logs                | Timestamp, IP address, path, status code, response size, user agent                                                                                                                                                      | 7 days                                         |
| Application and error logs | Timestamp, error type, status code, model, request ID, IP address shortened to the network (IPv4 /24, IPv6 /48)                                                                                                          | 7 days; error reports about 30 days            |
| Operating metrics          | Counters per model and pseudonymized API key, such as request count, latency, error rate, and token count                                                                                                                | 14 days                                        |
| Usage records              | Per request: timestamp, model, endpoint, input and output tokens, cost, status, user agent, a hash of the API key, the API key's name, project, and the optional `user` parameter. Daily totals per project and API key. | [TBD: statutory retention for billing records] |
| Client IP in usage records | IP address of the client that sent the request                                                                                                                                                                           | 30 days                                        |

Backups of usage records are kept for 4 weeks and then overwritten. Everything else is deleted automatically when its retention period ends; age is the only deletion criterion.

:::tip[Keep personal data out of metadata fields]
The optional `user` parameter and the names of your API keys and projects are stored as metadata. Use pseudonymous identifiers there, never names, email addresses, or health information.
:::

## Shared and dedicated hosting {#shared-dedicated}

With shared AI hosting, requests from different customers run on the same GPUs and the same model instances. Each request is processed on its own and doesn't change the model. [TBD: paragraph on separation between customers.]

With [Dedicated AI hosting](../70-dedicated/index.mdx), you get GPUs and a complete stack, from gateway to model servers and endpoint, that serve only you. No other mittwald customer's requests run on it. If you resell dedicated capacity to your own customers, the description of shared hosting applies to them, with you as the operator. If you have admin access to your dedicated gateway, any logging you turn on there is under your control.

## Your own applications {#applications}

If your application stores model output or embeddings, that storage happens in the services your application runs on, not in AI hosting. For example, when you run Open WebUI in mittwald's container hosting, chat history and uploaded documents live in that container's storage.

Whether a specific application complies with the GDPR or the EU AI Act depends on what it does. You may need user consent when it processes personal data, and the Terms of Use apply.
