## Client package releases


### mittwald PHP SDK v2.2.18 Release

The mittwald PHP SDK has been updated to version 2.2.18. This release focuses on enhancing API client error handling, specifically for HTTP 403 (Forbidden) responses when accessing invoice settings details. Key improvements include:

- Introduction of `InvoiceGetDetailOfInvoiceSettingsForbiddenResponse` to handle 403 responses with a standardized schema for validation and JSON serialization.
- Updates to `ContractClientImpl` to ensure HTTP 403 status codes are correctly routed to the new forbidden response handler.
- Necessary class imports and match-case statements have been added to support the new error handling mechanism.

For more details, visit the [release page](https://github.com/mittwald/api-client-php/releases/tag/v2.2.18).

### mittwald PHP SDK v2.2.17 Release Summary

The mittwald PHP SDK has been updated to version 2.2.17. This release introduces new features and enhancements aimed at improving security and usability.

#### New Features
- **Ingress Sender Login Protection**: A new `senderLoginProtection` boolean field has been added to the `Ingress` schema. When enabled, it restricts email sending from the Ingress and its SubIngresses exclusively to mailboxes within the same project.
- **Password Policy Schema**: New `Policy` and `PolicyRulesItem` schema classes have been introduced to represent structured password validation policies. This feature provides developers with access to minimum password complexity requirements and a list of configurable rule types.

#### Enhancements & API Updates
- **Structured Password Policy Responses**: The `PasswordValidationGetPasswordPolicyOKResponse` and its deprecated V2 counterpart have been updated to return a strongly typed `Policy` object instead of a raw string. This change enhances type safety and provides direct access to policy rules and complexity metrics.
- **OAuth Endpoint Documentation**: Inline documentation for the OAuth access token retrieval method has been refined. The updated description clarifies that the endpoint supports exchanging both authorization codes and refresh tokens, and notes that successful exchanges trigger a refresh token rotation.

For more details, please visit the [release page](https://github.com/mittwald/api-client-php/releases/tag/v2.2.17).

### mittwald PHP SDK v2.2.16 Release

The mittwald PHP SDK has been updated to version 2.2.16. This release focuses on schema and documentation enhancements to improve integration and developer experience. Key updates include:

- Clarification of field requirements for AI hosting orders and machine type specifications to ensure compatibility with available articles.
- Updated descriptions for `monthlyTokens` and `requestsPerMinute` in the AI Hosting Order schema, emphasizing the need for exact matches with available articles via the `/articles` endpoint.
- Added validation descriptions for the `machineType` field in the Machine Type Specification schema, aligning it with article matching requirements.
- Enhanced PHPDoc comments and schema metadata to improve autocomplete, documentation generation, and developer guidance.

For more details, visit the [release page](https://github.com/mittwald/api-client-php/releases/tag/v2.2.16).

### mittwald PHP SDK v2.2.15 Release Summary

The mittwald PHP SDK has released version v2.2.15, which introduces new features and updates to enhance functionality and user experience. 

#### New Features
- **Activity Log Schemas for Backup Operations**: This release includes a comprehensive suite of auto-generated PHP schema classes for modeling backup-related activity log events. These schemas offer structured data handling, JSON schema validation, serialization capabilities, and immutable builder methods. Supported activity log events include:
  - `backup.created` and `backup.deleted` (covering standard, export, and schedule deletions)
  - `backup.description-updated`
  - `backup.expiration-updated`
  - `backup.export-requested`
  - `backup.restore-requested`
  - `backup.schedule-created`
  - `backup.schedule-interval-updated`
  - `backup.schedule-ttl-updated`

  Each event type is paired with dedicated `Changes`, `Parameters`, and `Name` classes, enforcing strict typing and providing utilities for seamless API integration.

#### Domain API Client Updates
- **Method Deprecation**: The `resendContactVerificationEmail()` method in `DomainClient` is now deprecated. Users are advised to migrate to the `POST /v2/domains/{domainId}/actions/resend-email` endpoint.
- **Behavior Clarification**: Documentation for the `resendDomainEmail()` operation has been expanded to clarify its scope and constraints, including details on when a `412` Precondition Failed error will be returned.

For more details, visit the [release page](https://github.com/mittwald/api-client-php/releases/tag/v2.2.15).
