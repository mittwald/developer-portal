In the week of 11/13/2026 to 11/20/2026, the LeadFyndr API was removed following the discontinuation of the LeadFyndr product. In addition, new endpoints for AIssistant chats, AuthInfo2 domain checks and compromised password lookups were added, and several response schemas were updated.

:::info LeadFyndr has been discontinued

The LeadFyndr product has been discontinued. As a consequence, all LeadFyndr-related API operations (operation IDs prefixed with `leadfyndr-`) and their `de.mittwald.v1.leadfyndr.*` schemas have been removed from the API.

If you still have integrations using these operations, please remove them. Apart from this, the changes listed below are not breaking.

:::

## Summary

- All LeadFyndr operations and schemas have been removed due to the discontinuation of the LeadFyndr product (see above).

- The following optional properties have been added to the response with a `200` status for the operation `GET /v2/ai-hosting-keys` (Operation ID: `ai-hosting-user-get-keys`):
  - `/items/tokenUsage/keyAvailable`
  - `/items/tokenUsage/keyLimit`

- New endpoints have been added:
  - `GET /v2/aissistant-chats` (Operation ID: `aissistant-list-chats`) to list the chats of the authenticated user.
  - `DELETE /v2/aissistant-chats/{chatId}` (Operation ID: `aissistant-delete-chat`) to delete a chat of the authenticated user.
  - `GET /v2/aissistant-chats/{chatId}` (Operation ID: `aissistant-get-chat`) to get one chat of the authenticated user.
  - `PUT /v2/aissistant-chats/{chatId}` (Operation ID: `aissistant-save-chat`) to save the whole chat after a finished answer.
  - `POST /v2/aissistant-chats/{chatId}/actions/run` (Operation ID: `aissistant-run-chat`) to run the AIssistant on a chat and stream its answer.
  - `POST /v2/authinfo2/check-domain` (Operation ID: `domain-check-authinfo2`) to check if a domain is eligible for AuthInfo2.
  - `GET /v2/compromised-password-hashes/ranges/{hashPrefix}` (Operation ID: `hibp-get-compromised-password-hash-range`) to get the leaked-password suffixes of a SHA-1 prefix.

- The response property 'message' has become required for the status '429' for the following operations:
  - `POST /v2/authenticate` (Operation ID: `user-authenticate`)
  - `POST /v2/authenticate-mfa` (Operation ID: `user-authenticate-mfa`)
  - `POST /v2/register` (Operation ID: `user-register`)

- The response property 'type' has become required for the status '429' for the following operations:
  - `POST /v2/authenticate` (Operation ID: `user-authenticate`)
  - `POST /v2/authenticate-mfa` (Operation ID: `user-authenticate-mfa`)
  - `POST /v2/register` (Operation ID: `user-register`)

## Client package releases


### Release v2.2.30 of mittwald PHP SDK

The mittwald PHP SDK has released version v2.2.30, which focuses on improving error handling for the `ExtensionGenerateSessionToken` endpoint. This update introduces dedicated support for HTTP 412 (Precondition Failed) responses. The marketplace client now effectively parses, validates, and structures error payloads when precondition checks fail, replacing generic fallback handlers with specific response objects.

#### New Features
- **HTTP 412 Precondition Failed Handling**: A new `ExtensionGenerateSessionTokenPreconditionFailedResponse` has been added to handle `412` status codes during session token generation. The `MarketplaceClientImpl` has been updated to direct these responses to the new handler, ensuring consistent error reporting and structured `Error` body parsing for precondition failures.

For more details, visit the [release page](https://github.com/mittwald/api-client-php/releases/tag/v2.2.30).

### mittwald PHP SDK v2.2.29 Release Summary

The mittwald PHP SDK has been updated to version 2.2.29. This release introduces several new features, improvements, and deprecations. 

#### Features
- Added explicit support for handling HTTP 412 Precondition Failed errors in contract ordering and tariff preview workflows. This includes new structured response classes and client-side type mapping to help developers manage precondition violations effectively:
  - `OrderCreateOrderPreconditionFailedResponse`
  - `OrderCreateTariffChangePreconditionFailedResponse`
  - `OrderPreviewOrderPreconditionFailedResponse`
  - `OrderPreviewTariffChangePreconditionFailedResponse`
- Updated `ContractClientImpl` to handle HTTP 412 status codes with the appropriate typed error responses.

#### Improvements
- Unified error schema for rate limit responses by refactoring `TooManyRequests` response handling for user authentication and registration endpoints. This change replaces redundant local response body classes with a shared `de.mittwald.v1.commons.Error` schema, ensuring consistency in error payload structures.

#### Deprecations
- Deprecated the following Order schemas due to the discontinuation of the LeadFyndr product:
  - `LeadFyndrOrder`
  - `LeadFyndrOrderPreview`
  - `LeadFyndrOrderPreviewResponse`
  - `LeadFyndrTariffChange`
  
  Requests targeting these schemas will now result in a `LeadFyndrDiscontinued` error.

For more details, visit the [release page](https://github.com/mittwald/api-client-php/releases/tag/v2.2.29).

### mittwald PHP SDK v2.2.28 Release Summary

The mittwald PHP SDK has been updated to version v2.2.28. This release includes significant changes and new features:

- **Breaking Changes**: The `LeadFyndr` client and all related components have been removed. This includes the deletion of files under `src/Generated/V2/Clients/LeadFyndr/` and `src/Generated/V2/Schemas/Leadfyndr/`. The `Client` and `ClientImpl` no longer support the `leadFyndr()` method.

- **New Features**: A new method `checkAuthinfo2(CheckAuthinfo2Request $request): CheckAuthinfo2OKResponse` has been added to the `DomainClient` interface and `DomainClientImpl`. This introduces a new `CheckAuthinfo2` namespace, enabling a streamlined process for checking domain eligibility for AuthInfo2 transfers. The API now sends a `POST` request to `/v2/authinfo2/check-domain` to verify domain eligibility, providing detailed diagnostic reasons if a domain is ineligible.

- **Internal Refactoring**: Several classes from the deprecated LeadFyndr module have been repurposed to support the new `CheckAuthinfo2` functionality. Updates have been made to request/response validation schemas, HTTP method mappings, and URL builders to align with the revised API specification.

For more details, visit the [release page](https://github.com/mittwald/api-client-php/releases/tag/v2.2.28).
